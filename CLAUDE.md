# CLAUDE.md

Guidance for Claude Code (and other code agents) working in this repository.

## Project summary

`zomogoldapp` is a Flutter jewellery catalog app for Zomo Jewellers (Hyderabad, India). It targets Android, iOS, and Web (Linux/macOS/Windows scaffolds also exist but are not the primary platforms). Backend is Google Firebase: Firebase Auth (phone OTP), Cloud Firestore, and Firebase Storage. Live gold/silver rates are pulled from an external HTTP feed (dpgold.in).

The app is a catalog, not a marketplace — there is no in-app checkout. Users browse and tap "Order on WhatsApp" or "Call to Order" to contact a hard-coded sales number (`+918790343501`).

## Commands

Day-to-day development:

```bash
flutter pub get                          # install dependencies
flutter run                              # run on the connected device
flutter run -d chrome                    # run web build
flutter analyze                          # static analysis (uses analysis_options.yaml)
flutter test                             # run unit/widget tests (see caveat below)
flutter build apk --release              # release Android build
flutter build ios --release              # release iOS build (run on macOS)
flutter build web --release              # release web build
```

Caveat: `test/widget_test.dart` is the **default Flutter counter test** generated by `flutter create`. It expects a `+` icon and a counter — neither exists in this app — so `flutter test` will fail until that file is rewritten or deleted. Do not assume the test suite is green.

## Architecture at a glance

Three-layer organization under `lib/`:

```
lib/
├── main.dart           # Firebase init, deep-link handling, MaterialApp + routes
├── theme/app_theme.dart  # AppColors (purple swatch), AppText sizes, AppTheme.lightTheme
├── models/             # Plain Dart data classes + Firestore (de)serialization
│   ├── product_model.dart        # ProductModel  (Products collection)
│   ├── product_rate_model.dart   # ProductRateModel (product_rate collection)
│   ├── wish_list_model.dart      # WishlistModel (Wishlist collection)
│   ├── price_calculator.dart     # Static price math (MRP + selling price)
│   └── product_sort.dart         # ProductSortType enum
├── dao/                # Firestore access; one DAO per collection
│   ├── product_dao.dart
│   ├── product_rate_dao.dart
│   └── wish_list_dao.dart
└── screens/            # All UI; flat folder, no per-feature subfolders
```

There is **no state-management library** (no Provider/Riverpod/Bloc). Each screen is a `StatefulWidget` that owns its data and calls DAO methods directly. Cross-screen data (e.g. categories) is shared via the `CategoryService` singleton or by passing values through navigation arguments.

### Data flow

1. UI screens (`lib/screens/*.dart`) call DAO methods.
2. DAOs (`lib/dao/*.dart`) wrap `FirebaseFirestore.instance.collection(...)` calls and map docs to models.
3. Models (`lib/models/*.dart`) provide `fromSnapshot(DocumentSnapshot)` + `toJson()`.
4. Prices are computed client-side in `PriceCalculator` from the latest rate fetched from the `product_rate` collection.

### Firestore collections

| Collection      | Purpose                                                              |
| --------------- | -------------------------------------------------------------------- |
| `Products`      | Product catalog. Doc ID = `productId` (sequential string).           |
| `Category`      | Category metadata (`id`, `name`). Loaded by `CategoryService`.       |
| `Wishlist`      | One doc per (user, product) wishlist entry.                          |
| `product_rate`  | Append-only rate history for `GOLD` / `SILVER`.                      |
| `sequences`     | Counter docs (`product_sequence`, `wishlist_sequence`) for IDs.      |

For full field-level reference, see `DATA_MODEL.md`.

### Auth

Phone OTP via Firebase Auth. Web and native code paths differ in `phone_login_screen.dart`:

- **Web** uses `signInWithPhoneNumber` → `ConfirmationResult.confirm(otp)`.
- **Native** uses `verifyPhoneNumber` (with `verificationCompleted`/`codeSent` callbacks) → `PhoneAuthProvider.credential` → `signInWithCredential`.

Country code is hard-coded to `+91`.

### Deep linking

`main.dart` listens to `AppLinks().uriLinkStream`. URLs of the form `https://zomogold.com/product/{productId}` push `ProductDetailsViewPage`. The same URL is what `product_view_page.dart` shares via WhatsApp.

## Key conventions and gotchas

**Firebase web config is hard-coded in `main.dart`.** When `kIsWeb` is true, `Firebase.initializeApp` receives the API key, app ID, project ID, etc. inline. Native platforms use `google-services.json` (Android) and `GoogleService-Info.plist` (iOS) — only the Android one is currently committed. Don't add a `firebase_options.dart` (this project doesn't use FlutterFire CLI's generated options).

**Firestore reads are direct, not abstracted.** Several screens (`home_screen.dart`, `grid_screen.dart`, `search_screen.dart`, `filter_screen.dart`, `product_details.dart`) call `FirebaseFirestore.instance.collection('Category')` etc. directly instead of going through DAOs. When adding a new feature, prefer extending the relevant DAO.

**`home_screen.dart` has a stray `main()` function** at the top of the file (lines 14-18) — likely from copy-paste during scaffolding. Leave it alone unless asked; it's harmless because `lib/main.dart` is the real entry point.

**`category_screen.dart`, `cart_screen.dart`, `orders_screen.dart` are stubs.** They render placeholder text and are wired into the bottom nav. Real implementations are not yet built.

**Product IDs are sequential strings** generated by reading/incrementing `sequences/product_sequence.nextId`. This is **not race-safe** under concurrent admin writes — there's no transaction. Same pattern in `wishlist_sequence`. If you implement multi-admin product creation, switch to `FirebaseFirestore.runTransaction` or use Firestore auto-IDs.

**Prices are computed in the client.** `PriceCalculator.calculateProductMRP` does:
- For gold: `(carats / 24) * metalRate * grams + stoneWeight * stoneCost + makingCharges`
- For silver/other: `metalRate * grams + stoneWeight * stoneCost + makingCharges`
- Making charges are either flat (added) or `%` (percentage of pre-making total). Note: the app currently always passes `makingChargeType: "Flat"` from `grid_screen.dart`, `product_card.dart`, and `product_view_page.dart` regardless of the value entered in the admin form — the chosen type isn't persisted on `ProductModel`.

**`PriceCalculator.calculateSellingPrice` subtracts `discountPercent` as a flat rupee amount** (`mrp - discountPercent`), despite the parameter name. This is a known inconsistency.

**The admin entry points are inside the user app.** The "Profile" tab in the bottom nav of `home_screen.dart` opens `GoldRatesScreen` (admin), and from there the "Product update" tab opens the product creation form. There is no auth-gated admin role check.

**External rate API.** `gold_rate.dart` fetches `https://statewisebcast.dpgold.in:7768/...` and parses tab-separated text lines containing `GOLD`+`999`+`/ 10 Gm` or `SILVER 30 KG PAN India`. Brittle to upstream format changes.

**The "Login as guest" button in `phone_login_screen.dart` has an empty `onPressed: () {}`.** Guest mode is not implemented.

**Country/locale.** `supportedLocales: const [Locale('en', 'US')]`, but currency and phone format are India-specific (₹, +91). Don't use Intl number formatting for currency without checking — most price strings are formatted manually as `'₹ ${value.toStringAsFixed(0)}'`.

## Theme

`AppColors.purple` (`#6C4EE3`) is the brand color. Several screens hard-code their own purples (`Color(0xFF7F55B5)` in `product_details.dart` / `product_view_page.dart`, `Color(0xFF6B52A1)` in `grid_screen.dart` / `filter_screen.dart`, `Color(0xFF673AB7)` in `gold_rate.dart` / `history_screen.dart`). When making visual changes, prefer `AppColors`/`AppTheme` rather than introducing yet another shade.

## Dependencies worth knowing

- `firebase_core`, `firebase_auth`, `cloud_firestore`, `firebase_storage` — Firebase
- `app_links` — deep linking (≥ Android 12 intent handling, custom URL scheme)
- `flutter_quill` — rich text editor for product info / specifications (stored as JSON delta strings in Firestore)
- `image_picker` + `reorderables` — multi-image product upload (max 10) with drag-to-reorder thumbnails
- `flutter_typeahead` — search autocomplete in `search_screen.dart`
- `fl_chart` — line chart for `history_screen.dart`
- `photo_view` — pinch-zoom in `full_screen_image.dart`
- `url_launcher` — `tel:` and `wa.me/` links for ordering
- `shared_preferences` — recent searches (max 5)
- `another_flushbar` — top toast in product creation
- `http` + `xml` — external rate feed (xml is in pubspec but parsing in `gold_rate.dart` is line-based, not XML)

## When making changes

- **New Firestore field** → update the model's constructor, `fromSnapshot`, and `toJson`. Existing docs without the field need defaults (most fields already use `?? defaultValue`).
- **New screen** → put it in `lib/screens/`, register a route in `main.dart` only if you need named navigation; otherwise push directly with `MaterialPageRoute`.
- **New DAO method** → keep return types as `Future<T>` for one-shot reads/writes and `Stream<List<T>>` for live queries (matches existing patterns).
- **Color/typography changes** → prefer extending `AppColors` / `AppText` in `theme/app_theme.dart` over adding new constants in screen files.
- **Don't introduce a state management package** without discussing with the maintainer — the codebase is consistently `StatefulWidget` + DAO calls.
